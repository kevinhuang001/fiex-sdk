# Plugin internationalization

Core owns the locale (`zh-CN`, `zh-TW`, or `en`). Plugins must not infer it from the operating system or browser. Simplified Chinese source messages are the fallback when an entry is missing.

Browser panels create one `createI18n({ en, 'zh-TW': traditional })` runtime per panel and await `client.i18n.bind(runtime)` before rendering. The binding initializes the runtime from the bridge handshake and forwards `locale.changed` on the existing channel. Subscribe to the runtime to update existing React components or explicitly marked DOM copy; do not recreate the iframe, client, terminal, or operation state on locale changes. The binding returns an unsubscribe function.

Native plugins use `i18n::Catalog::from_json(english, traditional)` and `catalog.t(source)`. Translation uses the SDK's current request locale, inherited by SDK background tasks. `i18n::format(template, &[("0", value)])` substitutes named or numbered placeholders once, leaving braces in filenames and server responses intact. Localize the template before substitution.

Only authored display messages belong in catalogs. IDs, methods, JSON keys, ResourceRefs, paths, filenames, document contents, and raw remote data retain their original meaning. Use structured status fields or error reasons for control flow instead of matching translated messages.
